# Discovery Web Piscine

## Project Overview

This project is part of the Discovery Web Piscine and introduces the fundamentals of Git, GitHub, version control, and collaborative development workflows.

The project demonstrates how to create and manage a Git repository, track changes, create commits, connect a local repository to GitHub, and maintain clear project documentation.

## Objectives

- Understand the basics of Git and version control.
- Create and manage a local Git repository.
- Track and record changes using commits.
- Connect a local repository to GitHub.
- Push project changes to a remote repository.
- Practice professional project documentation.
- Understand a basic Git workflow for development.

## Git Workflow

A typical Git workflow consists of four main steps:

1. **Edit** — Create or modify project files.
2. **Add** — Stage the changes with `git add`.
3. **Commit** — Save a snapshot of the changes with `git commit`.
4. **Push** — Upload the committed changes to GitHub with `git push`.

This workflow makes it easier to organize development and keep a reliable history of project changes.

## Why Git Makes Development Easier

Git makes development easier because it provides version control for a project. Instead of having to manually keep multiple copies of files, Git records changes over time and allows developers to see how a project evolved.

Git also safeguards code by keeping a history of previous versions. If a change introduces a problem, developers can inspect earlier commits and restore or compare previous versions of the project.

Another important advantage is collaboration. Multiple developers can work on the same project, record their changes independently, and share their work through platforms such as GitHub. Git provides tools for combining changes and managing different development branches.

Overall, Git provides a structured way to track history, protect project progress, and collaborate with other developers.
